# AACommu — 상황인지 기반 지능형 AAC 시스템

청각장애인이 소음이 심하고 절차가 복잡한 서비스 환경(카페·식당·병원 등)에서 **타인의 도움 없이 주도적으로 의사소통**할 수 있도록 돕는 모바일 AAC(보완대체의사소통) 플랫폼. 사용자의 위치·상황(Context)을 자동 인지해 최적의 대화를 선제적으로 추천하고, 소음에 강인한 한국어 STT로 상대방의 말을 실시간 텍스트로 보여주는 **양방향 소통 시스템**이다.

---

## 문제 정의

기존 AAC 도구가 현장에서 외면받는 세 가지 한계를 해결하는 것을 목표로 한다.

| 한계 | 내용 |
|------|------|
| **상황 맥락의 부재** | 카테고리를 직접 선택·탐색해야 함 (예: 음료→커피→아메리카노, 4~5단계 터치). 인지 부하 증가, 속도 저하 |
| **소음 환경 취약성** | 카페·식당의 배경 소음(70~80dB)에서 범용 STT의 인식률(WER) 급락 |
| **단방향 소통의 한계** | 표현(TTS) 위주 설계로, 상대방(청인)의 말을 이해하는 수용 언어 지원 부족 |

핵심 전략: **위치 기반 서비스(LBS) + 대규모 언어 모델(LLM)** 을 결합해 상황을 능동 파악하고 대화를 선제 제시한다.

---

## 시스템 아키텍처

3계층 구조로 구성된다.

```
┌─────────────────────────────────────────────────────────────┐
│  Client (Flutter, iOS/Android 단일 코드베이스)                │
│   · GPS 위치 수집  · 마이크 음성 녹음(AAC/aacADTS)            │
│   · STT 결과 + 추천 문장(Chunk) 표시  · TTS 발화             │
│   · Naver Map SDK 기반 위치 인지, Bottom Sheet 대화 UI       │
└───────────────┬─────────────────────────────────────────────┘
                │ RESTful API (비동기)
┌───────────────▼─────────────────────────────────────────────┐
│  Backend Middleware (Spring Boot 3.3.3 / Java 17)            │
│   · Controller → Service → Repository 계층형 아키텍처        │
│   · 대화 세션 관리(H2 In-memory) — 문맥(history) 영속화      │
│   · AI 서버 중계(RestTemplate), DTO 매핑, 타임아웃 예외처리  │
└───────────────┬─────────────────────────────────────────────┘
                │ POST /predict
┌───────────────▼─────────────────────────────────────────────┐
│  Intelligent Dialogue Server (FastAPI / Python)             │
│   · STT Processor    → Naver Clova NEST 로 음성→텍스트       │
│   · Context Manager  → 장소 정보 + 대화 로그 관리            │
│   · Generation Engine→ KoGPT2 로 추천 문장 3~5개 생성        │
└─────────────────────────────────────────────────────────────┘
                │ 외부 연동
        Map API (Kakao/Google, POI 카테고리 식별)
        Naver Clova Speech (NEST) STT
```

### 계층별 역할
- **사용자 단말(App)** — GPS로 위치 수집, 마이크로 상대방 음성 녹음 후 서버 전송, STT 결과와 추천 답변 표시.
- **상황 인지 모듈** — GPS 좌표를 외부 Map API와 연동해 현재 장소의 POI 카테고리(카페·병원·관공서 등)를 식별.
- **지능형 대화 서버** — STT 처리, 문맥 관리, KoGPT2 기반 문장 생성을 담당.

## 기술 스택 및 선정 근거

| 영역 | 채택 기술 | 선정 이유 |
|------|-----------|-----------|
| **STT 엔진** | Naver Clova Speech (NEST) | 소음 환경에서 최저 WER, End-to-End 학습으로 배경음 분리·화자 분리(Diarization) 우수, 국내 리전 처리 |
| **언어 모델** | KoGPT2 (Fine-tuned) | 한국어 특화 경량(약 1.25억 파라미터) 모델 → 빠른 실시간 추론, 도메인 파인튜닝 용이, 저비용 |
| **Client** | Flutter | iOS/Android 단일 코드베이스, 강력한 Accessibility API |
| **AI 서버** | FastAPI (Python) | 비동기 I/O로 음성 스트림·LLM 추론 병렬 처리, PyTorch 호환 |
| **Middleware** | Spring Boot 3.3.3 (Java 17) | 트래픽 안정성·확장성, 세션 기반 문맥 관리 |

**모델 선정 비교 요지**
- STT: Naver Clova NEST > Google Cloud STT / AWS Transcribe (한국어 인식률·소음 강인성에서 우위).
- LLM: KoGPT2(Decoder-only, 초경량·실시간)를 채택. GPT-4는 API 레이턴시·비용 부담, BERT는 Encoder-only로 문장 생성에 부적합.

## 핵심 방법론

### 1. 위치 기반 상황 인지 및 자동 모드 전환 (Context-Aware Mode Switching)
Geofencing으로 메뉴 탐색 과정을 자동화한다.
- **위치 감지·필터링** — 배터리 효율을 위해 GPS를 5~10초 주기로 수집, **칼만 필터(Kalman Filter)** 로 위치 오차 보정.
- **POI 매칭** — 반경 20m 내 시설 카테고리 코드 분석(예: `CE7=카페`, `HP8=병원`) 후 가장 신뢰도 높은 장소를 현재 컨텍스트로 확정.
- **자동 전환** — 카페 감지 시 [카페 모드], 병원 감지 시 [병원 모드] UI·어휘셋 즉시 로드, 식별 불가 시 [일반 대화 모드] 유지.

### 2. LLM 기반 대화 예측·추천 (Predictive Dialogue Generation)
고정 스크립트가 아닌 문맥을 이해하는 생성형 모델을 사용한다.
- **프롬프트 구성** — 스페셜 토큰으로 화자 턴을 구분:
  ```
  <bos> <context: cafe> <sys> 어서오세요, 주문 도와드릴까요? <usr> 아이스 아메리카노 한 잔 주세요. <sys> 드시고 가시나요? <usr> (Predict Target)
  ```
- **생성 로직** — Beam Search / Top-k Sampling으로 상위 3~4개 후보 문장 생성(긍정·부정/대안·기타 등 변이 포함).
- **추천 제시** — 후보 문장을 버튼으로 표시, 터치만으로 즉시 TTS 발화 → 텍스트 입력 불필요.

### 3. 소음 대응 음성 처리 파이프라인
- **클라이언트 전처리** — 마이크 어레이 **빔포밍(Beamforming)** 으로 화자 방향 증폭, **WebRTC Noise Suppression** 으로 배경 잡음 1차 필터링.
- **서버 인식** — 필터링된 오디오를 Naver Clova NEST로 전송. NEST는 학습 단계부터 소음 데이터 증강(Augmentation)으로 학습되어 잔존 소음 속 키워드를 정확히 추출.

## 머신러닝 학습 (KoGPT2 Fine-tuning)

### 데이터셋 구축
- **소스**
  - AI Hub 공공 데이터셋 — '소상공인/민원 질의응답', '주문/결제 음성 데이터' 등.
  - 자체 수집 — 실제 카페 주문 상황을 가정한 롤플레잉 스크립트 **2,000건**.
- **전처리**
  - 특수문자 제거 및 개인정보 비식별화.
  - KoGPT2 토크나이저 기준 토큰화, 스페셜 토큰(`<usr>`, `<sys>`, `<context>`) 삽입.
- **데이터 포맷 예시**
  ```json
  {
    "context": "cafe",
    "dialogue": [
      {"role": "sys", "text": "쿠폰 적립 하시나요?"},
      {"role": "usr", "text": "아니요, 괜찮습니다."}
    ]
  }
  ```

### 학습 설정
- **환경** — Python 3.8, PyTorch 1.10, Hugging Face Transformers.
- **베이스 모델** — SKT의 Pre-trained KoGPT2.
- **태스크** — Next Token Prediction 방식으로 파인튜닝.
- **하이퍼파라미터** — Epoch 5, Batch size 16, Warm-up steps 10%.
- **최적화** — Overfitting 방지를 위한 Early Stopping, 추론 속도 확보를 위한 모델 크기 최적화.

## 성능 평가 결과

### 정량적 평가
| 지표 | 결과 |
|------|------|
| **Perplexity (PPL)** | 베이스 모델 대비 약 **45% 감소** — 문맥 예측 능력 향상 |
| **BLEU Score** | 평균 **0.78** — 실사용 가능한 자연스러움 |
| **Keystroke Savings (KSR)** | 기존 방식 대비 조작 횟수 **70% 이상 절감** (터치 15~20회 → 1~2회) |
| **Task 완료 시간** | 평균 **약 1분 → 10초 내외**로 단축 |
| **WER (70dB 소음)** | Naver Clova **8.2%** vs Google STT 14.5% |

> KSR 시나리오: "아이스 아메리카노 샷 추가해서 주세요" 주문 — 매장 진입 시 자동 추천 버튼 팝업에서 선택.

### 정성적 평가
- **실험 대상** — 청각장애인 5명, 비장애인 5명, 수어 통역사 2명 / 소음 환경(약 70dB) 및 실제 카페 현장.
- **긍정 피드백** — "매장에 들어가자마자 문장이 떠서 당황하지 않고 주문", "점원의 말이 글로 보이니 마음이 편하다".
- **개선 반영** — 반말 투 지적 → 경어체 필터링 강화, 인터넷 불안정 문제 → 오프라인 기본 문장셋 캐싱 추가.

## 향후 과제
- **실내 정밀 측위** — GPS 실내/실외 구분 한계를 BLE 비콘·Wi-Fi 핑거프린팅으로 보완, '카운터 앞'과 '테이블 위'를 구분하는 초정밀 상황 인지.
- **멀티모달 확장** — 비전 AI(OCR) 결합으로 메뉴판 촬영 → 자동 텍스트 인식 → 터치 버튼 변환.

## 기대 효과 요약
- **사회적** — 자립 주문 경험을 통한 자기효능감 향상, 장애 인식 개선.
- **경제적** — 서비스직 고용 기회 확대, 서비스 산업의 포용성 증대.
- **기술적** — LBS + NLP를 결합한 '화행(Speech Act) 예측' 보조공학 모델 제시, 한국형 AAC 데이터·모델 확보.
